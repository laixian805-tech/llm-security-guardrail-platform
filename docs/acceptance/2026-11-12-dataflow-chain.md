# 数据外发链重建（2026-11-12）

这是本轮唯一一个"从事件级走到链级"的能力，也是平台最该回答的问题：

> 现有归因只说明"这个事件属于哪次调用"，说明不了"这次会话有没有把东西送出去"。

## 先说清它是什么、不是什么

| | |
| --- | --- |
| **是** | 同一会话内「读了敏感文件 → 中转 → 连到外部地址」这条**路径序列**的重建 |
| **不是** | 内容追踪。它不证明"这些字节被发出去了"，只证明"先读了、后外连了" |
| **为什么不做内容级** | 需要在端侧拦截读写内容，量级完全不同。宁可把边界写死，也不给一个看起来更强、实际说不清的结论 |

## 判据

| 环节 | 规则 | 数据来源 |
| --- | --- | --- |
| source | intent 的 `resource_hints` 命中敏感标记（`~/.ssh/`、`.env`、`credentials`、`Cookies`、`.kube/config` 等） | 端侧 hook 新提取的路径 |
| hop（强） | 后续 intent 碰到同一文件（同路径或同文件名） | intent 顺序 + hints |
| hop（弱/staging） | 敏感读取之后又写出**新**文件（`write/edit/create/compress` 等工具） | tool_name + hints |
| sink | `network_connect` 且目标 `is_global` 为真 | Audit 采集 |

**没有 sink 就不产链**。只读私钥不外发不算外发链——这条规则决定了它的误报率。

`sink` 判定用 `ipaddress.is_global` 而非 `not is_private`：文档保留段（`192.0.2/24`、`198.51.100/24`、`203.0.113/24`）在 Python 里算 private，但它们根本不可路由，不该当外发终点。

## 标注集结果：4 条恶意全抓、4 条良性零误报

| 序列 | 标签 | 检出 | 判定 | 置信度 | sink |
| --- | --- | --- | --- | --- | --- |
| 读私钥 → 写 tmp → 外连 | 恶意 | 1 | TP | **medium** | 45.33.32.156 |
| 读 .env → 直接外连 | 恶意 | 1 | TP | low | 93.184.216.34 |
| 读浏览器 Cookie → 压缩 → 外连 | 恶意 | 2 | TP | low | 104.21.14.9 |
| 读 .git-credentials → 外连 | 恶意 | 1 | TP | low | evil.example.net |
| 读配置、无外连 | 良性 | 0 | TN | — | — |
| **读私钥 → git push 到 github** | 良性 | **0** | **TN** | — | — |
| 读 .env 写日志 | 良性 | 0 | TN | — | — |
| 读 kube config → 连内网 | 良性 | 0 | TN | — | — |

- **检出率 100%（4/4）**，**误报率 0%（0/4）**。
- 关键负样本「读私钥 + git push github」通过：`github.com` 在可信名单里，不产链。没有这一条，功能等于废掉——开发者每天要 push 几百次。

## 置信度梯度是刻意设计的

| 形态 | 置信度 | 理由 |
| --- | --- | --- |
| 敏感读 + 中转写 + 外连 | **medium** | 内容可能被搬到新文件，但仍证明不了流向 |
| 敏感读 + 直接外连 | low | 可能只是正常业务（git push、拉包） |
| （预留）内容级追踪 | high | **当前做不到，不提供** |

上限只到 medium 是诚实：路径级证据只能支撑到这一步。

## 两个实现细节（都是踩出来的）

1. **端侧的 `resource_hint` 原本是死字段**。归因服务的 `TEMPORAL_FEATURE`(0.35) 一直读 `summary.resource_hint`，而端侧 `summarize()` 从不产出它——那 0.35 分的弱关联在生产里永远不触发。本轮补上 `resource_hints`（路径列表，最多 4 条、家目录归一成 `~`、超长截断），并让控制面用同一套归一化。
2. **测试用例一开始全 FN**。原因是我拿 `203.0.113.9` / `198.51.100.7` / `192.0.2.44` 当"外部地址"，而这些是 RFC 5737 的文档保留段，Python 判为 private → 全被当成内网。换成真实公网地址后才测出真实行为。

## 缺口

- **只做单会话内**，跨会话（多个 agent 接力）不做。
- **不做内容级**，因此无法区分"读了私钥但只用了公钥部分"这类情况。
- **不落库**：按需计算，避免为启发式结果造历史表。要历史趋势需要另加持久化。
- 可信域名是硬编码列表（`github.com`、`pypi.org` 等），企业域名要显式加入 `TRUSTED_HOSTS`，否则会误报。
